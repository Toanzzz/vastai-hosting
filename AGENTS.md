# Project rules

- Headless Python 3.12 service. Use uv for dependency management, commands, and the committed `uv.lock`; `pyproject.toml` is the source of truth for dependencies and tools.
- Use a `src/` package layout with small one-directional modules (aim for 300 lines or less). Use Ruff for formatting and linting, ty for type checking, and pytest for tests.
- Pricing proposals (GPU price, and disk, upload and download rates) come from Gemini through `google-genai`; validate the response and all pricing bounds locally before any listing write. When Gemini is unavailable or its answer fails validation, the GPU proposal is the peer median minus $0.02, rounded half-up to the cent. Rates are validated separately: without a valid Gemini rate proposal, each rate is its peer median rounded half-up to the cent, or the listed rate when no peer reports one. The pricing cycle does not call `list_machine`. A listing write happens only when an allowed Telegram subscriber taps a suggested price or rates button within 48 hours of its market check, and the tapped values are checked against the configured bounds again first; the write keeps the live listed values for everything not tapped. Skip the write when market data is unavailable, when the suggestion matches the listed value, or when the suggestion is outside the configured bounds.
- Never include API keys in command arguments or logs. Never commit `.env`.
- After edits run, in order: `uv run ruff check .`, `uv run ruff format --check .`, `uv run ty check`, `uv run pytest`, `uv build`.
